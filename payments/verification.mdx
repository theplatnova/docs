title: "Verifying a Payment"

---

Before you mark an order paid and ship anything, confirm the payment with Platnova from your server. A webhook tells you something happened; verification proves it.

## `POST /v1/payments/verify`

```bash
curl -X POST https://api.platnova.com/v1/payments/verify \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"reference": "3e584f08-6a55-4b15-a97f-364a7d21071e"}'
```

`reference` can be any of:

- **the checkout `id`** you got when you created the checkout (best for plugins: you already stored it against the order);
- **the payment `reference`** from the `checkout.paid` webhook;
- **Platnova's reference for a payout** you sent: the `transaction_ref` that [`POST /v1/payments/send`](/payments/sending-payments) answered, or `data.reference` from a `transfer.*` webhook. If you never got it because Send timed out, [look the payout up by its `Idempotency-Key`](/payments/sending-payments#lost-the-answer).

Verification only ever finds your own business's payments, and it keeps working after the checkout itself has expired.

## Response: a paid checkout

```json
{
  "status": true,
  "data": {
    "id": "",
    "ref": "the payment's transaction reference",
    "currency": "NGN",
    "amount": 25000,
    "paid_amount": 25375,
    "fee": 375,
    "type": "receive_payment",
    "status": "success",
    "entry": "credit",
    "message": "Checkout payment received",
    "checkout_id": "3e584f08-6a55-4b15-a97f-364a7d21071e",
    "payment_method": "bank_transfer",
    "created_at": "2026-10-27T16:02:11Z",
    "updated_at": "2026-10-27T16:02:11Z"
  },
  "error": [],
  "message": "operation was successful"
}
```

| Field | Meaning |
|---|---|
| `id` | A payout's id. Empty for a checkout payment. |
| `ref` | The payment's transaction reference. Quote it to support. |
| `amount` | What **you** were credited, in `currency`. |
| `paid_amount` | What the payer sent. The difference is `fee`. |
| `fee` | Platnova's fee on this payment. |
| `currency` | Uppercase currency code. |
| `status` | `success` for a received checkout payment. For a payout it is the payout's status. |
| `checkout_id` | The checkout this payment settled. |
| `payment_method` | How the payer paid: one of the [payment method ids](/checkout/initiating-checkout#payment-methods-offered). |
| `type`, `entry` | `receive_payment` / `credit` for a checkout payment. |

## Response: a payout

```json
{
  "status": true,
  "data": {
    "id": "9b2f7c1e-3d4a-4f6b-8e21-5c0d9a7b3f10",
    "ref": "BTRNSF7HeRoy4CRl6hcOOqAzwAeo0WLLMMbtQ2",
    "currency": "NGN",
    "amount": 100.5,
    "fee": 10.75,
    "type": "send_payment",
    "status": "success",
    "entry": "debit",
    "message": "Transfer to John Doe",
    "created_at": "2026-11-03T13:05:12Z",
    "updated_at": "2026-11-03T13:05:40Z"
  },
  "error": [],
  "message": "operation was successful"
}
```

`ref` is the same value Send Payment answered as `transaction_ref`. `amount` is what was sent and `fee` is charged on top. A payout has no `checkout_id`, `payment_method` or `paid_amount`. Its `status` is one of:

| Status | Meaning |
|---|---|
| `pending` | On its way to the recipient's bank. |
| `pending_approval` | Waiting for a team member to approve it (dashboard sends only). |
| `success` | The recipient's bank has it. |
| `cancelled` | It failed (the amount and fee are back in your wallet), or it was reversed after it succeeded (the amount is back; the fee is kept). |
| `failed` | Only a scheduled payout that found too little in the wallet when it was due. Nothing was debited. |

**A failed payout reads `cancelled`, not `failed`.**

## Response: not paid (or not yours)

A reference with no payment behind it answers `400` with `message` `payment not found`. `data.code` tells the cases apart:

```json
{ "status": false, "data": { "code": "checkout_unpaid", "status": "pending" }, "error": [], "message": "payment not found" }
```

| `data.code` | Meaning |
|---|---|
| `checkout_unpaid` | One of your checkouts, not paid yet. `data.status` is `pending` while the payer can still pay, `expired` once its 7 days are over. |
| `payment_not_found` | Nothing of yours has this reference. |

**Not found never means a payout failed.** A failed payout is found, with status `cancelled`. Don't send a payout again because Verify did not find it; [look it up by its `Idempotency-Key`](/payments/sending-payments#lost-the-answer) first.

## Fulfil an order safely

<Steps>
<Step title="Receive checkout.paid">
Check the [signature](/webhooks/signatures), store the event, answer `200`.
</Step>
<Step title="Verify">
Call `POST /v1/payments/verify` with the checkout `id` you stored against the order.
</Step>
<Step title="Compare">
Require `status` = `success`, `checkout_id` = your stored id, and `currency` (case-insensitive) and the amount to match the order. With `fee_bearer` `customer` (the default) you are credited the full checkout `amount`; with `merchant` you are credited `amount` less `fee`.
</Step>
<Step title="Fulfil once">
Mark the order paid in the same database transaction as a unique record of the checkout id, so a repeated webhook can never fulfil twice.
</Step>
</Steps>
