Before you mark an order paid and ship anything, confirm the payment with Platnova from your server. A webhook tells you something happened; verification proves it.

## `POST /v1/payments/verify`

```bash
curl -X POST https://api.platnova.com/v1/payments/verify \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"reference": "3e584f08-6a55-4b15-a97f-364a7d21071e"}'
```

`reference` can be any of:

- **the checkout `id`** you got when you created the checkout (best for plugins: you already stored it against the order);
- **the payment `reference`** from the `checkout.paid` webhook;
- **the reference of a payout** you sent with [`POST /v1/payments/send`](/payments/sending-payments).

Verification only ever finds your own business's payments, and it keeps working after the checkout itself has expired.

## Response: a paid checkout

```json
{
  "status": true,
  "data": {
    "id": "",
    "ref": "the payment's transaction reference",
    "currency": "NGN",
    "amount": 25000,
    "paid_amount": 25375,
    "fee": 375,
    "type": "receive_payment",
    "status": "success",
    "entry": "credit",
    "message": "Checkout payment received",
    "checkout_id": "3e584f08-6a55-4b15-a97f-364a7d21071e",
    "payment_method": "bank_transfer",
    "created_at": "2026-10-27T16:02:11Z",
    "updated_at": "2026-10-27T16:02:11Z"
  },
  "error": [],
  "message": "operation was successful"
}
```

| Field | Meaning |
|---|---|
| `id` | A payout's id. Empty for a checkout payment. |
| `ref` | The payment's transaction reference. Quote it to support. |
| `amount` | What **you** were credited, in `currency`. |
| `paid_amount` | What the payer sent. The difference is `fee`. |
| `fee` | Platnova's fee on this payment. |
| `currency` | Uppercase currency code. |
| `status` | `success` for a received checkout payment. For a payout it is the payout's status. |
| `checkout_id` | The checkout this payment settled. |
| `payment_method` | How the payer paid: one of the [payment method ids](/checkout/initiating-checkout#payment-methods-offered). |
| `type`, `entry` | `receive_payment` / `credit` for a checkout payment. |

## Response: not paid (or not yours)

A checkout that has not been paid, or a reference that is not one of your payments, answers `400`:

```json
{ "status": false, "data": {}, "error": [], "message": "payment not found" }
```

Verification cannot tell "not paid yet" apart from "no such payment". If you need to know whether a checkout still exists, read it with [`GET /v1/checkout/{id}`](/checkout/retrieving-checkout) (`pending` = exists, not paid).

## Fulfil an order safely

<Steps>
<Step title="Receive checkout.paid">
Check the [signature](/webhooks/signatures), store the event, answer `200`.
</Step>
<Step title="Verify">
Call `POST /v1/payments/verify` with the checkout `id` you stored against the order.
</Step>
<Step title="Compare">
Require `status` = `success`, `checkout_id` = your stored id, and `currency` (case-insensitive) and the amount to match the order. With `fee_bearer` `customer` (the default) you are credited the full checkout `amount`; with `merchant` you are credited `amount` less `fee`.
</Step>
<Step title="Fulfil once">
Mark the order paid in the same database transaction as a unique record of the checkout id, so a repeated webhook can never fulfil twice.
</Step>
</Steps>
