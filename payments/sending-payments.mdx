Send money transfers using multiple payment methods. This guide covers how to send payments and track their status.

## Sending a Payment

Send a payment by specifying the payment method and recipient details in `info`. Example for a bank transfer:

```bash
curl -X POST https://api.platnova.com/v1/payments/send \
  -H "X-API-KEY: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: order-1042-payout" \
  -d '{
    "from_amount": 500.00,
    "from_wallet_id": "43a2b75e-5c59-429e-872a-2a54c7b17e37",
    "to_currency": "NGN",
    "payment_method": "bank_transfer",
    "info": {
      "account_number": "0123456789",
      "bank_code": "058",
      "account_name": "Jane Smith"
    },
    "reference": "PAY001",
    "payment_type": { "type": "instant" }
  }'
```

## Payment Parameters

### Required Fields

- **from_amount** – Amount to send (source currency)
- **from_wallet_id** – Wallet ID to debit from
- **to_currency** – Destination currency (e.g. NGN, USD)
- **payment_method** – One of: `bank_transfer`, `card`, `mobile_money`, `wallet`, `tag_transfer`, `defi`, `revolut`, `paypal`, `cashapp`, `zelle`
- **info** – Recipient details; required fields depend on `payment_method` (e.g. for `bank_transfer`: `account_number`, `bank_code`, `account_name`; for `tag_transfer`: `tag_id`)

### Optional Fields

- **reference** – Your own reference, for your records. A second payment with a reference you already used is refused. It is not an idempotency key: for safe retries, send the `Idempotency-Key` header (see [Lost the answer?](#lost-the-answer))
- **payment_type** – `instant`, `scheduled`, or `recurring` (default: instant)
- **is_save_to_beneficiary** – Save recipient as beneficiary

## Finding the bank_code

`bank_code` is not a CBN or SWIFT code; it is the code our payment provider uses for that bank in that country. Get it from [List banks](/api-reference/banks/list) for the recipient's country, and use it as-is:

1. `GET /v1/banks/{country_code}` lists every bank with its `code`.
2. For Ghana and Kenya, `GET /v1/banks/{country_code}/{bank_code}` lists branches; pass the chosen `branch_code` in `info.branch_code`.
3. `POST /v1/banks/verify` resolves the account number to the holder's name before you send.
4. If you only have an account number, `POST /v1/banks/suggest` returns banks we have paid it through before.

Cache the bank list for at most a day. All four endpoints need your API key.

## Payment Response

```json
{
  "status": true,
  "data": {
    "transaction_ref": "BTRNSF7HeRoy4CRl6hcOOqAzwAeo0WLLMMbtQ2",
    "status": "pending",
    "from_amount": 500,
    "to_amount": 500,
    "from_currency": "ngn",
    "to_currency": "ngn",
    "method": "bank_transfer",
    "created_at": "Monday, 3 November, 14:05"
  },
  "error": [],
  "message": "operation was successful"
}
```

Store `transaction_ref`: it is Platnova's reference for the payout. Verify Payment answers it as `ref`, and `transfer.*` webhooks carry it as `data.reference`. `created_at` here is a readable time in your business's time zone; Verify Payment gives a machine-readable one.

## Payment Status

Payouts complete asynchronously. Watch for the `transfer.*` [webhooks](/webhooks/overview) or check with Verify Payment. A payout's `status` is one of:

| Status | Meaning |
|---|---|
| `pending` | Accepted and on its way to the recipient's bank. |
| `pending_approval` | Waiting for a team member to approve it. Only dashboard sends wait; an API key's send never does. |
| `success` | The recipient's bank has it. |
| `cancelled` | It failed (the amount and fee are back in your wallet), or it was reversed after it succeeded (the amount is back; the fee is kept). |
| `failed` | Only a scheduled payout that found too little in the wallet when it was due. Nothing was debited. |

**A failed payout reads `cancelled`, not `failed`.**

The `transfer.failed` webhook is the exception: its `data.status` is `failed`, while the payout itself reads `cancelled` from then on.

## Verifying Payment Status

Check a payout with the `transaction_ref` Send Payment returned:

```bash
curl -X POST https://api.platnova.com/v1/payments/verify \
  -H "X-API-KEY: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "reference": "BTRNSFxxxx"
  }'
```

`400 payment not found` means no payment of yours has that reference. It never means the payout failed: a failed payout is found, with status `cancelled`. See [Verifying a payment](/payments/verification).

## Lost the answer?

If Send Payment times out or the connection drops, you don't have `transaction_ref`, and you can't tell whether the payout was made. Don't send it again with a new reference: that can pay twice. Instead:

1. **Retry with the same `Idempotency-Key` and the same body.** If the first request finished, you get its answer and nothing is sent again. If it is still running, you get `409 request_in_progress`; wait for `Retry-After` and retry. If it keeps answering `409`, the first request stopped without an answer: look it up instead.
2. **Or look it up** with [`GET /v1/payments/by-key/{key}`](/api-reference/payments/by-key). `payment.ref` is the `transaction_ref` you missed and `payment.status` is the payout's status now. `nothing_created: true` means nothing was sent: send it again under a **new** key.

Both only work if the original request carried an `Idempotency-Key`, so send one on every payout.

## Payment Methods

The API supports multiple payment methods; pass `payment_method` and the matching `info` shape:

| Method | Description | Example info fields |
|--------|-------------|---------------------|
| **bank_transfer** | Bank transfers (NGN, USD, etc.); ACH, RTP, wire for USD | `account_number`, `bank_code`, `account_name` |
| **card** | Card payments | Card-specific recipient details |
| **mobile_money** | Mobile money (e.g. Ghana) | Phone, provider, etc. |
| **tag_transfer** | Wallet-to-wallet transfer | `tag_id` |
| **wallet** | Wallet payments | Wallet identifier |
| **defi** | DeFi | Asset, network, address, etc. |
| **revolut** | Revolut | Revolut recipient details |
| **paypal** | PayPal | PayPal identifier |
| **ussd** | USSD | USSD channel details |
| **cashapp** | Cash App | Cash App identifier |
| **zelle** | Zelle | Zelle recipient details |

Availability depends on currency and region. See the [Send Payment API](/api-reference/payments/send) for the exact `info` fields per method.

## Payment Limits

Payment limits may apply based on:

## Best Practices

- Verify recipient account details before sending
- Include payment references for easy tracking
- Monitor payment status regularly
- Keep sufficient wallet balance
- Handle failed payments appropriately
