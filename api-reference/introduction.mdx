Welcome to the Platnova Business API Reference. Our RESTful API provides programmatic access to virtual accounts, cards, payments, and other financial services, allowing you to integrate Platnova's capabilities into your business applications.

## Base URL

All API requests should be made to:

**Production:**
```
https://api.platnova.com
```

**Sandbox:**
```
https://sandbox.api.platnova.co
```

## Authentication

Send your API key in the `X-API-Key` header on every request. See the [Authentication guide](/authentication).

```bash
X-API-Key: YOUR_API_KEY
```

Do not send it as `Authorization: Bearer`, and don't send a dashboard session token alongside it. Putting the key in the URL (`?api_key=`) is deprecated; see [Versioning](/versioning).

Some routes (webhook management, statements, team settings) are dashboard-only and do not accept API keys.

## Request Format

Send `Content-Type: application/json` and `X-API-Key` on every request. On requests that create or move money, also send an `Idempotency-Key` (see [Errors](/errors#retrying-safely)).

## OpenAPI spec and Postman collection

- OpenAPI 3 spec: [`/api-reference/openapi.json`](https://docs.platnova.com/api-reference/openapi.json)
- Postman collection: [`/api-reference/platnova.postman_collection.json`](https://docs.platnova.com/api-reference/platnova.postman_collection.json). Import it and set the `baseUrl` and `apiKey` collection variables.

## Response Format

All API responses are returned in JSON format with the following structure:

### Success Response
```json
{
    "status": true,
    "data": {
        // Response data here
    },
    "error": [],
    "message": "operation was successful"
}
```

### Error Response
```json
{
    "status": false,
    "data": {},
    "error": [],
    "message": "Error message here"
}
```

### Validation Error Response
```json
{
    "status": "error",
    "message": "Validation failed",
    "errors": {
        "field_name": [
            "This field is required"
        ]
    }
}
```

## Rate Limits

Some endpoints are rate limited per client IP, per minute. Those endpoints send these headers:
- `X-RateLimit-Limit`: Maximum requests per minute
- `X-RateLimit-Remaining`: Remaining requests in the current minute
- `X-RateLimit-Reset`: When the window resets (Unix timestamp)

Some endpoints have specific rate limits:
- Card creation: 4 requests per window
- Card reveal: 10 requests per window
- Virtual account creation: 2 requests per window

## Error Handling

The API uses standard HTTP status codes:

- `200` - Success
- `400` - Bad Request (the request was refused; read `message` and `data.code`)
- `401` - Unauthorized (invalid API key)
- `403` - Forbidden (insufficient permissions)
- `404` - Not Found
- `409` - Conflict (a request with the same `Idempotency-Key` is still running)
- `422` - Unprocessable Entity (validation errors, or an `Idempotency-Key` reused for a different request)
- `429` - Too Many Requests (rate limit exceeded)
- `500` - Internal Server Error

See our [Error Handling guide](../errors) for detailed error information.

## Pagination

List endpoints support pagination using query parameters:

- `page`: 0-indexed page number (default: 0)
- `size`: Number of items per page (default: 10)
- `sort`: Sort order (optional)
- `filters`: Filter criteria (optional)

Response includes pagination metadata:
```json
{
    "page": 0,
    "size": 10,
    "max_page": 5,
    "total_pages": 6,
    "total": 60,
    "last": false,
    "first": true,
    "visible": 10
}
```
