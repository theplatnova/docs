The API answers with standard HTTP status codes and one of three JSON shapes. Branch on the **HTTP status** first, then on `data.code` when it is present. `message` is written for a person; don't parse it.

## Response shapes

### 1. Standard response (most success and error answers)

```json
{
  "status": false,
  "data": { "code": "request_in_progress" },
  "error": [],
  "message": "This request is still being processed. Nothing new was done."
}
```

- `status` is a **boolean**: `true` for 2xx, `false` otherwise.
- `data` holds the result on success. On some errors it holds a machine-readable `code` and details (for example `data.missing` on `entity_not_active`). It is `{}` when there is nothing to add.
- `error` is an array, usually empty.

### 2. Validation failure (HTTP 422)

A body that is missing a required field or has a field of the wrong type:

```json
{
  "status": "error",
  "message": "Validation failed",
  "errors": {
    "amount": ["This field is required"],
    "email": ["This field is required"]
  }
}
```

<Warning>
In this shape `status` is the **string** `"error"`, not a boolean, and the details are in `errors` (plural), keyed by field. Treat any HTTP 422 as a validation failure regardless of the body.
</Warning>

### 3. Rate limited (HTTP 429)

```json
{ "status": false, "data": {}, "error": [], "message": "please wait for few minutes, try again later" }
```

with `X-RateLimit-Limit`, `X-RateLimit-Remaining` and `X-RateLimit-Reset` headers (see [Authentication](/authentication#rate-limits)).

## Status codes

| Status | Meaning | Retry? |
|---|---|---|
| `400` | The request was refused. Read `message` and `data.code`. Nothing was done. | Not unchanged; fix the request |
| `401` | Missing or invalid API key (`un-authorized access`). | No; fix the key |
| `403` | Not allowed: the business is not live (`entity_not_active`), or the key or user lacks permission. | No |
| `404` | Not found (for example a checkout older than 7 days). | No |
| `409` | A request with the same `Idempotency-Key` is still running (`request_in_progress`), or a conflict named by `data.code` (for example `reference_in_progress`, `account_limit_reached`, `customer_id_conflict`, `customer_exists`). Nothing new was started. | For `request_in_progress` and `reference_in_progress`: yes, the same request, after a short wait (`Retry-After` seconds when sent). Otherwise read `data.code` |
| `413` | Request body too large (`request_too_large`). | No |
| `422` | Validation failed (shape 2), or an `Idempotency-Key` reused with a different body. | No; fix the request |
| `429` | Rate limited (shape 3). | Yes, after `X-RateLimit-Reset` |
| `5xx` | Our error. The outcome of a money request may be unknown. | Yes, **with the same `Idempotency-Key`** so it can't run twice |

## Error codes

| `data.code` | Status | What it means | What to do |
|---|---|---|---|
| `entity_not_active` | 403 | Your business is not live yet. `data.missing` lists what is left. | Finish [going live](/going-live) |
| `idempotency_key_required` | 400 | This route requires an `Idempotency-Key` and none was sent. | Send one |
| `idempotency_key_invalid` | 400 | The key is not 1–255 of letters, digits, `_`, `.`, `:`, `-`. | Fix the key |
| `idempotency_key_reused` | 422 | The key was already used for a different request. | Use a new key for a new request |
| `request_in_progress` | 409 | The first request with this key is still running. | Retry with the same key |
| `idempotency_unavailable` | 503 | We couldn't start the request. Nothing was sent. | Retry with the same key |
| `request_too_large` | 413 | Body over the size limit. | Send less |
| `duplicate_reference` | 400 | `POST /v1/payments/send`: you already used this `reference`. `data.transaction_ref` is the existing payment's. Nothing new was sent. | Check the existing payment with [Verify Payment](/payments/verification) |
| `duplicate_reference` | 400 | Virtual accounts: the `reference` already belongs to another account of your business (another customer, currency or amount). On a dynamic account whose time is up, `data.status` is `expired`. | Use a new reference |
| `invalid_reference` | 400 | Virtual accounts: the `reference` is not 1–64 of letters, digits, `_`, `.`, `:`, `-`, or `reference` and `order_reference` differ. `data.field` names the field. | Fix the reference |
| `reference_in_progress` | 409 | Virtual accounts: the first request with this reference is still opening the account. | Retry the same request shortly |
| `account_limit_reached` | 409 | `POST /v1/virtual-accounts/create`: nothing was opened. Either the bank can't open another account for this customer (`data.accounts` lists their accounts there), or the person already holds your business's limit of open accounts, counted across customer ids that share a BVN (`data.limit`, `data.active`). | Use an existing account, choose another bank with `codes`, use a [dynamic account](/virtual-accounts/dynamic-accounts), or ask support to raise the limit |
| `customer_id_conflict` | 409 | `POST /v1/virtual-accounts/create`: the customer's BVN was verified and `id_number` is a different one. `data.customer_id` is the customer. Nothing was opened. | Use a new `customer_id` for a different person |
| `invalid_customer_details` | 422 | `POST /v1/virtual-accounts/create`: the bank rejected the customer's details. `data.field` names the detail when the bank did. | Fix the details, then retry |
| `invalid_bank` | 400 | `POST /v1/virtual-accounts/create` or `/dynamic`: `bank` is not `paga` or `nombank` (or disagrees with `codes`). | Send `paga`, `nombank`, or leave it out |
| `bank_not_offered` | 400 | `bank` names a bank your business doesn't open accounts at. | Leave `bank` out, or contact support |
| `account_in_progress` | 409 | Another request is opening this customer's account right now. | Retry shortly |
| `bank_unavailable` | 503 | `POST /v1/virtual-accounts/create`: the bank can't open accounts right now. `data.retryable` is `true`. | Retry later, or use a [dynamic account](/virtual-accounts/dynamic-accounts) |
| `virtual_account_not_found` | 404 | `GET /v1/virtual-accounts/by-reference/{reference}`: no account was opened with this reference. | Check the reference |
| `duplicate_customer_reference` | 400 | Customers: another of your customers already has this `reference`. `data.id` is that customer. | Use that customer, or a different reference |
| `customer_exists` | 409 | `POST /v1/customers` without a `reference`: a customer with this email already exists. `data.id` is that customer. Customers created with your own id (`reference`, or `customer_id` on virtual-account requests) are never refused for their email. | Use `data.id`, or send your own id as `reference` |
| `payment_not_found` | 400 | `POST /v1/payments/verify`: no payment with this reference for your business. For a payout, it was never created. | Safe to resend with the same `reference` |
| `checkout_unpaid` | 400 | `POST /v1/payments/verify`: your checkout exists but is not paid. `data.status` is `pending` or `expired`. | Wait for `checkout.paid` |
| `order_unpaid` | 400 | `POST /v1/payments/verify`: nothing has been paid into the account for this order reference. `data.status` is `pending` (still open) or `expired`. | Wait for `account.funded` |
| `line_items_invalid` | 400 | `line_items` don't add up to `amount`, or a line is invalid. `message` says which. | Fix the lines |

Refunds have their own codes; see [Refunds](/checkout/refunds).

### Common messages without a code

| Message | Status | Where |
|---|---|---|
| `currency is not supported for checkout` | 400 | `POST /v1/checkout` |
| `invalid success_url` / `invalid cancel_url` | 400 | `POST /v1/checkout`: send an absolute `http(s)` URL |
| `checkout not found` | 404 | `GET /v1/checkout/{id}` |
| `payment not found` | 400 | `POST /v1/payments/verify`: see `data.code` (`payment_not_found`, `checkout_unpaid` or `order_unpaid`) |
| `customer was not found` | 400 | A customer id none of your customers has (as our id or your `reference`). On virtual-account requests, send the customer's details to create them |
| `bank account is already added` | 400 | `POST /v1/virtual-accounts/create` without `reference`: the customer already has an account at this bank |
| `something went wrong, please contact support` | 400/500 | Unexpected failure; include the time and your reference when contacting support |

## Retrying safely

Send an `Idempotency-Key` on every request that creates or moves money. Then a retry after a timeout, a `5xx` or a `409` either returns the first answer or runs once, never twice. See [Making retries safe](/checkout/initiating-checkout#making-retries-safe-idempotency-key).
