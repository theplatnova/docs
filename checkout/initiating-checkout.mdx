Start a checkout session with `POST /v1/checkout`. This creates a hosted payment page and returns a checkout `id` and `url`.

## Example request

```bash
curl --location 'https://sandbox.api.platnova.co/v1/checkout' \
  --header 'X-API-KEY: YOUR_API_KEY' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Bearer YOUR_JWT_TOKEN' \
  --data-raw '{
    "email": "jonathanemma121@gmail.com",
    "amount": 2000.15,
    "currency": "ngn",
    "payment_options": [
      {
        "id": "defi"
      }
    ]
  }'
```

## Request fields

- **email**: Customer email for the checkout.
- **amount**: Amount to collect.
- **currency**: Currency code (for example `ngn`).
- **payment_options**: Optional. The ways the payer may pay. **Leave it out to offer every method that is live for the currency** — that is the recommended default, and new methods reach your payers as we switch them on. Send it only to restrict the checkout to specific methods. Supported `id` values:

| `id` | What the payer does | Currencies |
|---|---|---|
| `tag_transfer` | Pays from their Platnova wallet by scanning a QR code | all |
| `bank_transfer` | Transfers to a one-time account number | NGN |
| `card` | Enters their card on a secure page | NGN, USD, EUR, GBP, CAD |
| `apple_pay` | One tap on an iPhone, iPad or Mac | USD, EUR, GBP, CAD (NGN soon) |
| `google_pay` | One tap in Chrome or on Android | USD, EUR, GBP, CAD (NGN soon) |
| `opay` | Approves the payment in their OPay app | NGN |
| `bank_account` | Picks their bank and approves in that bank's own app or online banking | NGN |
| `ussd` | Dials a code from any phone, no internet banking needed | NGN |
| `mobile_money` | Approves a prompt on their phone, paying from a Ghanaian, Kenyan, Ugandan, Rwandan or Tanzanian wallet in that currency at Platnova's rate | all |
| `crypto` | Pays in crypto | all |

A method that is not live for the checkout's currency is left off the page even if you list it. Mobile money is cross-currency: the payer sees what they will pay in their own currency, you are settled the checkout amount in yours, and the conversion is Platnova's, not yours. `novatag` and `defi` are accepted as older spellings of `tag_transfer` and `crypto`.

### Crypto payments

The payer is shown an invoice in coins for the checkout amount. What arrives can differ slightly: wallets and networks shave off fees, and payers sometimes send a little less or more. Platnova values the coins that actually arrived at the market rate when the payment settles, and never credits more than the crypto processor delivered. A payment that covers the invoice is booked as successful even if the processor calls it `partially_paid`. One that falls short is booked as partially completed, and you are credited what arrived.

Each crypto deposit records the breakdown: the amount requested, the coins received and their coin, what those coins were worth, the rate, the fee and the amount credited. You can see it in the transaction details on the dashboard, in the transaction CSV export (the `Requested`, `Received`, `Coins`, `Pay Currency` and `Rate` columns) and in the [`defi.payment` webhook](/webhooks/overview#defi-payment) (`booking_status`, `requested_amount`, `rate`).

## Payment option values

To restrict a checkout, list the methods you want:

```json
[
  { "id": "bank_transfer" },
  { "id": "ussd" },
  { "id": "opay" },
  { "id": "card" }
]
```

To offer everything, omit `payment_options` from the request.
